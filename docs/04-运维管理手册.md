## 1. 日常巡检（每天 1 分钟）

```bash
ssh root@YOUR_SERVER_IP

# 一屏看全
echo "=== GPU ==="; nvidia-smi --query-gpu=memory.used,memory.total,utilization.gpu,temperature.gpu,power.draw --format=csv
echo "=== MEM ==="; free -h
echo "=== DISK ==="; df -h /mnt/disks/nvme | tail -1
echo "=== 容器 ==="; docker ps --filter name=video- --format "table {{.Names}}\t{{.Status}}"
echo "=== 栈健康 ==="; curl -s localhost:8080/api/health
```

**健康标准**：

| 指标 | 正常 | 告警 | 危险 |
|---|---|---|---|
| GPU 温度 | < 65°C | 65-78°C | > 80°C |
| 可用内存 | > 30GB | 15-30GB | < 15GB |
| NVMe 可用 | > 200GB | 50-200GB | < 50GB |
| 容器状态 | Up | 反复重启 | Exited |

## 2. 启动 / 停止

> ⚠️ **硬底线（2026-10-23）**：SDF 只能用 **`docker compose -p sdf`** 管理。
> 禁止 `docker run` / `docker restart sdf-api` / Portainer / Unraid Docker 页单独启停。
> 改了 compose 文件后跑 `docker compose -p sdf up -d`；自检矛盾用 `./deploy/check_stack.sh`。
> 栈名固定 `sdf`，容器固定 `sdf-api` / `sdf-comfyui`。

```bash
cd /mnt/disks/nvme/docker/compose/sdf

# 起（-p 是双保险，compose 文件已写 name: sdf）
docker compose -p sdf up -d

# 看栈内容器（不要用 docker ps -a 拼凑）
docker compose -p sdf ps

# 自检：栈名 / compose 标签 / 同项目 / 健康（非 0 = 不合规）
./deploy/check_stack.sh

# 停（保留容器）
docker compose -p sdf stop

# 停并删容器（保留数据）
docker compose -p sdf down

# 只重启 ComfyUI（释放显存）
docker compose -p sdf restart comfyui

# 只重启 API
docker compose -p sdf restart api
```

## 4. 显存管理（最常做的事）

### 4.1 看谁在占

```bash
nvidia-smi --query-compute-apps=pid,process_name,used_memory --format=csv
```

### 4.2 释放 ComfyUI 占用的显存（不重启）

```bash
curl -s -X POST http://YOUR_SERVER_IP:8188/free \
  -H 'Content-Type: application/json' \
  -d '{"unload_models":true,"free_memory":true}'

# 或在容器里
docker exec sdf-api python -c "from pipeline import comfy; comfy.free_vram()"
```

### 4.3 强制释放（ComfyUI 卡死时）

```bash
docker compose restart comfyui
sleep 30
nvidia-smi --query-gpu=memory.used --format=csv
```

### 4.4 让出 GPU 给其它栈

```bash
docker compose stop comfyui          # API 保留，队列照常可提交

# 用完恢复
docker compose start comfyui
```

## 5. 故障排查表

### 5.1 提交任务无响应

```bash
# 1. ComfyUI 活着吗
curl -s localhost:8188/system_stats | head -c 100

# 2. 队列里有什么
curl -s localhost:8188/queue | python3 -m json.tool | head -40

# 3. 日志有没有在执行
docker compose logs --tail=50 comfyui
```

### 5.2 CUDA out of memory

```bash
# 1. 先释放
docker compose restart comfyui && sleep 40

# 2. 降档重试
#    - 分辨率降一档（768x1344 → 576x1024）
#    - 步数降（8 → 6）
#    - 时长降（10s → 5s）

# 3. 看是否别的栈抢显存
nvidia-smi
```

### 5.3 进程"莫名消失"、容器报 ExitCode=0

**这是 host RAM OOM，不是显存问题。**

```bash
# 确认
dmesg -T | grep -i "oom-kill" | tail -20

# 典型输出
# Out of memory: Killed process 12345 (python3) total-vm:... 
```

**处理**：
1. 立刻确认 swap 挂上了：`free -h` 的 Swap 行
2. 停掉其它吃内存的容器（LM Studio、PhotoPrism、Jellyfin）
3. 长期：加内存到 128GB

### 5.4 渲染出来的视频没有声音

```bash
# 检查产物音轨
ffprobe -v error -show_streams -select_streams a output/xxx.mp4
```

**原因**：
- H3 的音频 VAE 没加载 → 检查 `vae/minimax_h3_audio_vae_fp32.safetensors` 是否存在
- `VAEDecodeAudio` 节点没连到 `CreateVideo` → 检查 `workflow.build_h3()`
- 用的是 5B 引擎（5B 本来就没有音轨）

### 5.5 网页打不开

```bash
# API 容器活着吗
docker ps --filter name=sdf-api

# 端口占用
ss -lntp | grep 8080

# 直接测
curl -v http://YOUR_SERVER_IP:8080/api/health
```

### 5.6 分镜生成失败（LLM）

```bash
# 在容器里测
docker exec -it sdf-api python - <<'PY'
import os
from pipeline import script
print("BASE:", script.BASE_URL)
print("KEY:", "已配置" if script.API_KEY else "❌ 未配置")
print("MODEL:", script.MODEL)
try:
    print(script.chat([{"role":"user","content":"说'ok'"}]))
except Exception as e:
    print("失败:", e)
PY
```

**常见**：
- `ICOMPIFY_API_KEY` 未传进容器 → 检查 compose 的 `environment`
- 余额不足 → 401/402
- 返回 JSON 带 markdown 围栏 → 已被 `extract_json` 处理

## 6. 备份

### 6.1 备份什么

| 对象 | 大小 | 频率 | 方式 |
|---|---|---|---|
| `data/video.db` | < 10MB | 每天 | sqlite 备份 |
| `workflows/` | < 1MB | 变更时 | git |
| `docs/` | klein | 变更时 | git（已推 Gitea） |
| `output/` | 每集 200-500MB | 按需 | rsync 到 SATA |
| `models/` | 42GB | 不用备份 | 可从 ModelScope 重拉 |

**模型不备份**——重拉 15 分钟，备份占 42GB 不划算。

### 6.2 数据库备份脚本

```bash
#!/bin/bash
# /mnt/disks/nvme/docker/compose/sdf/deploy/backup_db.sh
set -e
SRC=/mnt/disks/nvme/docker/compose/sdf/data/video.db
DST=/mnt/disks/sata/Backup/Video
mkdir -p "$DST"
STAMP=$(date +%Y%m%d_%H%M)
sqlite3 "$SRC" ".backup '$DST/video_$STAMP.db'"
# 保留最近 30 份
ls -t "$DST"/video_*.db | tail -n +31 | xargs -r rm
echo "备份完成: $DST/video_$STAMP.db"
```

加到 crontab：

```bash
crontab -e
# 每天 4:30
30 4 * * * /mnt/disks/nvme/docker/compose/sdf/deploy/backup_db.sh >> /var/log/video-backup.log 2>&1
```

### 6.3 产物归档

```bash
# 完成的成片迁到 SATA 冷存
rsync -av --remove-source-files \
  /mnt/disks/nvme/docker/compose/sdf/output/*/E*/E*_final.mp4 \
  /mnt/disks/sata/Backup/Video/final/
```

### 6.4 恢复

```bash
docker compose stop api
cp /mnt/disks/sata/Backup/Video/video_20261021_0430.db \
   /mnt/disks/nvme/docker/compose/sdf/data/video.db
docker compose start api
```

## 9. 性能监控（可选）

写个简单采集，记录每镜耗时，用于容量规划：

```bash
docker exec sdf-api python - <<'PY'
from pipeline import db
import sqlite3
conn = db.connect()
rows = conn.execute("""
  SELECT engine, resolution, steps, AVG(duration_ms)/1000.0 avg_s, COUNT(*) n
  FROM shot WHERE status='done' AND duration_ms IS NOT NULL
  GROUP BY engine, resolution, steps ORDER BY engine
""").fetchall()
for r in rows:
    print(f"{r['engine']:6} {r['resolution']:10} {r['steps']}步  "
          f"均 {r['avg_s']:.0f}s  n={r['n']}")
PY
```

**这张表比任何网上的 benchmark 都准**——是这台机器的真实数据。攒够 50 条后回头更新 `router._COST`。

## 10. 应急联系

| 情况 | 动作 |
|---|---|
| GPU 温度 > 85°C 持续 | `docker compose stop comfyui`，检查机箱风道/风扇 |
| 磁盘 > 95% | 立即清理 output，否则 SQLite 写入失败 |
| 内存持续 < 10GB | 停 ComfyUI，排查谁在吃 |
| 数据损坏 | 停 api → 从备份恢复 db → 起 |
| 电源跳闸 | 检查 PSU 余量（A5000 230W 峰值） |
