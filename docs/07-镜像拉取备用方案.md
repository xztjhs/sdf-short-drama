# 镜像拉取慢的备用方案

> 2026-10-21 实测：Docker Hub 直连 583KB/s，docker.1ms.run 中途降到 216KB/s。
> 如果 `docker compose up` 卡在拉镜像，按这里的顺序试。

---

| 源 | 实测速度 | 状态 |
|---|---|---|
| Docker Hub 直连 | 583 KB/s | ❌ 5.7GB 需 2.7h |
| `docker.1ms.run` | 起 3.7MB/s，后掉到 216KB/s | ⚠️ 可用但慢 |

## 方案 A：继续等（最简单）

```bash
ssh root@YOUR_SERVER_IP
tail -f /mnt/disks/nvme/docker/compose/sdf/logs/docker_pull.log
# 完成后 retag
docker tag docker.1ms.run/yanwk/comfyui-boot:cu126-slim-20261019 \
           yanwk/comfyui-boot:cu126-slim-20261019
```

已下载约 3.9/5.7GB。慢但会完成。

---

## 方案 B：换 1panel 源（可复用已下载层）

```bash
ssh root@YOUR_SERVER_IP
docker pull docker.1panel.live/yanwk/comfyui-boot:cu126-slim-20261019
docker tag docker.1panel.live/yanwk/comfyui-boot:cu126-slim-20261019 \
           yanwk/comfyui-boot:cu126-slim-20261019
```

`Already exists` 的层会被复用，只补差异部分。

---

## 方案 C：用已有的 mmartial 镜像自建

.253 上已有一个 `mmartial/comfyui-nvidia-docker:ubuntu24_cuda12.8-latest`（11.6GB，含 CUDA 12.8 运行时，Python 3.12，**无 torch**）。

```bash
# 1. 建 Dockerfile.offline
cat > /mnt/disks/nvme/docker/compose/sdf/Dockerfile.comfy <<'EOF'
FROM mmartial/comfyui-nvidia-docker:ubuntu24_cuda12.8-latest

ENV DEBIAN_FRONTEND=noninteractive
RUN apt-get update && apt-get install -y --no-install-recommends \
      git curl libgl1 libglib2.0-0 && rm -rf /var/lib/apt/lists/*

# torch cu128（匹配镜像的 CUDA 12.8）
RUN pip3 install --break-system-packages --no-cache-dir \
      torch torchvision torchaudio --index-url https://download.pytorch.org/whl/cu128

# ComfyUI 主线（要含 H3 节点，需较新版本）
RUN git clone --depth 1 https://github.com/comfyanonymous/ComfyUI /opt/ComfyUI \
 && cd /opt/ComfyUI && pip3 install --break-system-packages --no-cache-dir -r requirements.txt

WORKDIR /opt/ComfyUI
EXPOSE 8188
CMD ["python3","main.py","--listen","0.0.0.0","--port","8188", \
     "--disable-pinned-memory","--fp16-intermediates","--reserve-vram","2.5"]
EOF

# 2. 构建（torch 约 2.5GB，从 pytorch.org 下，速度未知）
cd /mnt/disks/nvme/docker/compose/sdf
docker build -f Dockerfile.comfy -t sdf-comfyui:local .
```

**优点**：完全可控，版本明确，能确保含 H3 节点
**风险**：
- `download.pytorch.org` 在国内速度未知（实测 200 可达，未测速）
- 需要编译/安装一堆依赖，首次构建 20-40 分钟
- 镜像的 entrypoint 是 `/comfyui-nvidia_init.bash`，要用 `--entrypoint` 覆盖

## 方案 D：换更小的 ComfyUI 镜像

`yanwk/comfyui-boot` 有多个 tag：

| tag | 大小 |
|---|---|
| `cpu` | 3.6 GB |
| `cu130-slim` | 5.8 GB |
| `cu126-slim` | 6.8 GB |
| `nightly` | 4.4 GB |
| `cu126-megapak` | 10.6 GB（含所有常用节点） |

**不行**：cpu 版没有 CUDA。
**可试**：`nightly`（4.4GB，比 slim 小 2.4GB），但 nightly 可能不稳定。

## 方案 E：手动下载镜像层，`docker load`

在能快速访问 Docker Hub 的机器上：

```bash
# 有快网的机器
docker pull yanwk/comfyui-boot:cu126-slim-20261019
docker save yanwk/comfyui-boot:cu126-slim-20261019 | gzip > comfyui.tar.gz
# 传到 .253（内网，走 SMB/NFS 很快）
scp comfyui.tar.gz root@YOUR_SERVER_IP:/tmp/
# .253 上
gunzip -c /tmp/comfyui.tar.gz | docker load
```

**最优解**——如果手边有能直连 Docker Hub 快的机器（比如云主机）。
6.8GB 压缩后约 2.5GB，内网传输几分钟。

---

## 决策建议

1. **先看 1panel 源**（方案 B），如果它在 10 分钟内下完剩余部分就最省事
2. 不行就**方案 E**（找台快网机器导出导入）
3. 都没有才用**方案 C**（自建，可控但慢）

---

## 判断拉取是否真的卡死

```bash
# 每 30 秒看临时 blob 大小变化
a=$(ls -la /var/lib/docker/tmp/GetImageBlob* 2>/dev/null | awk '{s+=$5} END{print s+0}')
sleep 30
b=$(ls -la /var/lib/docker/tmp/GetImageBlob* 2>/dev/null | awk '{s+=$5} END{print s+0}')
echo "30s 增加 $(( (b-a)/1024/1024 )) MB"
```

- 增加 > 5MB/30s → 在动，等
- 增加 0 → 卡死，换源
- 文件消失且 `docker images` 出现 → 完成了

## 2026-10-21 00:50 实测记录（追加）

| 时间 | 源 | 速度 | 已下 |
|---|---|---|---|
| 00:07-00:25 | Docker Hub 直连（超时前） | 583 KB/s | — |
| 00:14-00:45 | docker.1ms.run | 3.7 MB/s → 216 KB/s | 3.9 GB |
| 00:47-00:52 | docker.1panel.live | 能复用已下载层，但新层卡在 `Pulling fs layer` | — |
| 00:55 | docker.1ms.run（独占） | **514 KB/s** | 3.9 GB |

**结论**：
- 国内拉 5.7GB 级别的镜像，**不要指望快**。500KB/s 是常态。
- 两个 pull 并行会**互相抢带宽**，反而更慢。**只开一个。**
- `.1panel.live` 的 `Pulling fs layer` 卡住不动时，说明它的 blob 存储在国内回源慢，不如 1ms。

**最省时的做法（下次直接用这条）**：
```bash
# 找台能快速访问 Docker Hub 的机器
docker pull yanwk/comfyui-boot:cu126-slim-20261019
docker save yanwk/comfyui-boot:cu126-slim-20261019 | zstd -3 > comfy.tar.zst
# 内网传到 .253（SMB 千兆，2.5GB 约 30 秒）
zstd -d -c comfy.tar.zst | docker load
```
