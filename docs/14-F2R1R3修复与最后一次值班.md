## 一、F2：Ref2VA 参考图失效（已修复，根因确认）

### 1.1 真正根因

`pipeline/workflow.py::build_h3_ref2va` 把参考图写成**嵌套 dict**：

```python
ref_images = {"ref_image_0": (node, 0)}     # ❌ 被静默丢弃
```

ComfyUI 的 Autogrow 输入在 API 格式里只认**带前缀的点号键**：

```python
"ref_images.ref_image_0": [node, 0]          # ✅
```

schema 校验不报错，但 `execute()` 收到的 `ref_images` 是空 `None`，
参考图**完全不参与采样**，人物长相 100% 由文字决定。

依据：ComfyUI 自身单测 `tests-unit/execution_test/dynamic_inputs_test.py`
Autogrow 用例就是 `{"rows.item0": 0.5}`。

### 1.2 决定性证据（三组同 seed 同提示词，只改参考图）

| 输入 | 抽帧 md5 |
|---|---|
| 0 张参考图 | `6be2e144c07f...` |
| 1 张整图 1800×1200 | `6be2e144c07f...` ← 完全相同 |
| 1 张脸部特写 640×640 | `6be2e144c07f...` ← 完全相同 |
| **改成点号键后** | `88694a8e79c9...` ← 变了，人物与照片一致 |

传 0 张和传 2 张不同图，输出**逐字节相同** —— 这是"参考图没生效"的铁证，
不可能是模型效果问题。

### 1.3 修复

```python
h3_inputs: dict[str, Any] = dict(clip=..., vae=..., prompt=..., ...)
for i, path in enumerate(refs):
    img = g.add("LoadImage", image=path)
    h3_inputs[f"ref_images.ref_image_{i}"] = (img, 0)
h3 = g.add("MiniMaxH3ReferenceToVideo", **h3_inputs)
```

回归测试 `scripts/test_ref2va_keys.py`（12 项，毫秒级，无需 GPU）：

```
✅ 使用点号键 ref_images.ref_image_0
✅ 不存在嵌套 dict（会被静默丢弃）
✅ 不存在无前缀扁平键（会报 unexpected kwarg）
✅ 多张顺序稳定 / 零参考图不产生 ref 键
```

## 二、音频：听不懂 + 啰嗦重复（已修复）

### 2.1 两个独立病因

**病因 A：提示词自相矛盾 → 半说半唱**

镜35 修复前的实际提示词：

```
画面：【本镜】…正在唱出这句歌词，口型与节奏匹配
音频：示例人物A的嘴唇开合，用普通话逐字说出这句台词："今天是个好日子"
```

H3 同时收到"唱"和"说"两个指令，输出就是含糊不清的乱语。

修复：`build_h3_prompt` 先判断这句是唱还是说
（关键词 唱/歌词/旋律/演唱/歌声），分支写不同指令。
另外：台词镜的 `sfx` 如果又写了"人声/歌/唱"，
会和台词指令打架 → 自动降级为"环境底噪"。

**病因 B：同一句台词塞进 11 个镜头**

```
镜35,39,43,49,52,55,58,61,64,67,70  dialogue 全是"今天是个好日子"
→ 成片里同一句反复唱 11 遍
```

修复两层：
1. `script.dedupe_dialogue()` — 同一句全片最多 1 次，多余的清空
   dialogue 并补 sfx=环境底噪
2. 分镜规则 11c 明确禁止；`storyboard_quality()` 会检出并报错

**附带修复**：7 字歌词配 8 秒镜头时，模型会把一句反复念来填时间。
现在按台词长度算 `per_sec`（唱 1.6 字/秒、说 2.6 字/秒），
台词不够撑时长就加"按正常语速一次说完，说完就停，不要重复"。

### 2.2 顺手修掉的名字重复

角色锚点本身以名字开头（`示例人物B，45岁中国男性…`），
外层又拼 `f"{name}：{text}"` → 提示词里出现 `示例人物B：示例人物B，45岁…`。
已在 `anchor_text()` 和定妆照 prompt 两处剥掉。

## 四、R3：关闭尾帧衔接（已落地）

`config/settings.yaml`：`chain_frames: true → false`

理由：Ref2VA 修好后每镜由参考图锁人物，不再需要尾帧接力。
开着会把后 70+ 镜焊成同一条镜头的延长 —— 示例人物A项目 75 镜
全是"同一个人在同一走廊后退"，就是这个效果。

## 六、F2 修复后暴露的新问题：参考图构图污染（已用分镜适配解决）

### 6.1 现象

Ref2VA 修好后，镜1（设定「全景」）连续 3 次重渲，**0.5s 还是全景，5s 后必定推成正面大特写**，
和定妆照构图一模一样。加「不要把镜头拉远」「一镜到底」都无效。

### 6.2 三组对照实验（同 seed、同 prompt、3 秒）

| 参考图 | 0.5s | 1.5s | 2.5s | 结论 |
|---|---|---|---|---|
| 正面头像定妆照 | 中景 | 半身 | **正面大特写** | 复刻参考图构图 |
| **无参考图** | 全景 | 全景（全身走动） | 全景 | 景别稳定，但**脸漂移**（头发变灰、五官不对） |
| 全身参考图 | 全景 | 中景 | 仍推成特写 | 只是推迟，压不住 |

再加一组「构图锁定放 prompt **最末尾**」+ 全身参考图 + 5 秒：

```
0.5s 全景 → 2s 侧脸特写 → 3.5s/4.8s 全是特写
```

**结论**：Ref2VA 的参考图参与每一步采样，模型不只抄脸，也抄构图。
文字指令（无论放前面还是末尾）都压不住这个几何先验。

### 6.3 解法：让分镜去适配模型，而不是对抗模型

既然 Ref2VA 稳定落在 **半身/中近景**，就把分镜按这个落点设计：

| 用途 | 做法 | 原因 |
|---|---|---|
| 人物戏 | 一律 **中景 / 中近景 / 近景 / 特写** | 落在 Ref2VA 的自然收敛区，构图不打架 |
| 交代空间 | 改用**空镜**（characters=[]） | 无人物 → 不挂参考图 → 走纯文本，景别完全可控 |

这恰好符合竖屏短剧的常规语法：人物贴身近，环境靠空镜带。

### 6.4 一个新项目里踩到的次级坑

- 单人镜头会莫名多出一个模糊路人 → 已加「画面中只有 X 一个人，不要有路人」约束
- 角色锚点自带名字，外层又拼 `name：` → 提示词出现「示例人物B：示例人物B，45岁…」→ 已剥除
- 定妆照 prompt 同样的名字重复 → 已修
