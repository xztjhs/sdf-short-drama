# 03 · 开发手册

> 改代码之前先读这篇。结构、契约、扩展点都在这。

---

## 1. 代码结构

```
pipeline/
├── db.py          SQLite 状态库（project/character/episode/shot/job）
├── comfy.py       ComfyUI 客户端（提交/轮询/释放显存）
├── workflow.py    工作流构造（程序化拼 API JSON）
├── router.py      镜头路由（H3 vs Wan2.2）
├── script.py      LLM 分镜生成（icompify）
├── worker.py      渲染工作器（串行、重试、成片）
└── assemble.py    ffmpeg 成片

web/
├── app.py         FastAPI（REST + 静态）
├── static/
│   └── index.html 单页前端（原生 JS，无构建）
├── Dockerfile
└── requirements.txt
```

**没有框架包袱**：无 ORM、无前端构建、无消息队列。纯 Python + 原生 JS + SQLite。

## 3. 核心接口契约

### 3.1 `db.py`

所有状态读写。**没有 ORM，直接 SQL**。

```python
db.init_db()                            # 建表（幂等）
pid = db.create_project("剧名", style="...")
eid = db.create_episode(pid, seq=1, script="...")
sid = db.add_shot(eid, seq=1, prompt="...", duration=5.0,
                  dialogue="台词", characters=["林晚"])
db.update_shot(sid, status="done", output_path="/output/...")
db.next_pending_shot()                  # FIFO 取下一个
db.stats(project_id)                    # 汇总
```

**关键约束**：`add_shot` 的 `characters` 传 list，内部会 json.dumps。`list_shots` 会反序列化回 list。

### 3.2 `comfy.py`

```python
comfy.alive() -> bool
comfy.system_stats() -> dict
comfy.submit(workflow_dict) -> prompt_id
comfy.wait(prompt_id, timeout=3600) -> history_dict
comfy.outputs_of(history, kind="images") -> [{"filename":...}]
comfy.free_vram()                       # 释放显存
comfy.upload_image(local_path) -> server_filename
comfy.interrupt()                       # 中断当前任务
```

**为什么用轮询不用 WebSocket**：ComfyUI 的 ws 在几分钟级任务里偶尔丢消息，而 `/history/{id}` 是权威来源。3 秒轮询对 6 分钟任务无感。

### 3.3 `workflow.py`

```python
wf = workflow.build_h3(prompt="...", resolution="768x1344", duration=5,
                       steps=8, seed=42, first_frame=None, turbo=True)
wf = workflow.build_wan22(prompt="...", resolution="544x960", duration=5)
```

返回 API 格式 dict（`{node_id: {class_type, inputs}}`），直接喂 `comfy.submit()`。

**图构造器 `Graph`**：自动分配 node id，用 `(node, 0)` 元组表达连接。

```python
g = Graph()
unet = g.add("UNETLoader", unet_name="x.safetensors")
enc  = g.add("CLIPTextEncode", text="hi", clip=(unet, 0))  # 连 unet 的 0 号输出
g.to_api()
```

### 3.4 `router.py`

```python
d = router.route(shot_dict, quality_first=False, forced_engine=None)
# -> RouteDecision(engine, reason, resolution, steps, priority)

plan, summary = router.plan_episode(shots, quality_first=False)
```

`RouteDecision.priority` 越小越先跑（有对白的 3，其余 6）。

### 3.5 `worker.py`

```python
worker.render_shot(shot, project_id=..., episode_seq=..., quality_first=False)
worker.run_episode(episode_id, progress=lambda ev: ...)
```

`run_episode` 内部有**全局锁** `worker.LOCK`，保证串行。

### 3.6 `assemble.py`

```python
t = assemble.Target(width=1080, height=1920, fps=24, crf=20, lufs=-16.0)
assemble.normalize_clip(src, dst, t)     # 统一画布+帧率
assemble.concat(parts, dst)              # 无损拼接
assemble.loudnorm(src, dst, t)           # 两遍响度归一化
assemble.burn_subtitles(src, dst, srt, t)
assemble.srt_from_shots(shots, srt_path) # 从镜头表生成字幕
assemble.assemble_episode(files, dst, subtitle_srt=..., target=t)
```

## 4. 常见扩展点

### 4.1 加一个新引擎

1. `workflow.py` 写 builder：

```python
def build_ltx2(*, prompt, resolution="720x1280", duration=5, steps=8, seed=0, **kw):
    g = Graph()
    unet = g.add("UNETLoader", unet_name="ltx2.safetensors")
    ...
    return g.to_api()

BUILDERS["ltx2"] = build_ltx2
```

2. `router.py` 加判定分支
3. `worker._COST` 加耗时基线
4. `docker-compose.yml` 模型目录挂载已有，无需改

### 4.2 改路由规则

编辑 `router.py` 的 `_ACTION_KW` / `_EMPTY_KW` 正则，或 `route()` 里的 if 链。

**注意**：改完跑 §2.2 的路由测试，确认没意外翻转。

### 4.3 加 API 端点

`web/app.py` 里加 Pydantic 模型 + 路由函数。自动出现在 `/docs`。

### 4.4 改前端

`web/static/index.html` 是单文件。改完 `docker compose restart api` 即可（静态文件随镜像复制）。

**开发时**可以挂载覆盖，不用重建：

```yaml
volumes:
  - ./web/static:/app/static:ro
```

### 4.5 换 LLM

`script.py` 顶部：

```python
BASE_URL = os.environ.get("ICOMPIFY_BASE_URL", "https://api.icompify.com/v1")
MODEL = os.environ.get("ICOMPIFY_MODEL", "deepseek-v4-pro")
```

只要是 OpenAI-compatible 就能换（DeepSeek 官方、Kimi、本地 vLLM 都行）。

```bash
          open('/tmp/wf.json','w'), indent=2, ensure_ascii=False)

# 拖进 ComfyUI 画布（需转换格式）或直接看结构
```

### 5.3 卡在某个 node

`comfy.wait()` 的 `on_progress` 会报当前 node：

```python
comfy.wait(pid, on_progress=lambda e: print(e))
# {'node': '3', 'elapsed': 45.2}
```

对照 `wf["3"]["class_type"]` 就知道卡在哪。

### 5.4 OOM 后必做

```python
comfy.free_vram()          # 先释放
# 然后改一个参数（seed / steps / 分辨率）再跑，不要原样重试
```

`worker.RETRY_STRATEGY` 已实现这个逻辑。

## 6. 代码规范

| 项 | 约定 |
|---|---|
| 语言 | 注释中文，标识符英文 |
| 类型 | 用 `from __future__ import annotations` + 内置泛型 |
| 错误 | 自定义异常继承 `RuntimeError`（`ComfyError`/`FFmpegError`/`LLMError`） |
| 日志 | 容器 stdout，`json-file` driver 限 50MB×5 |
| 依赖 | 后端只加 `fastapi`/`uvicorn`/`pydantic`。**不引入 ORM/队列/前端框架** |

## 9. 性能调优方向

| 优化 | 预期收益 | 代价 |
|---|---|---|
| H3 步数 8→6 | -25% 时间 | 音频质量下降 |
| 5B 用 lightx2v 4-step | -33% 时间 | 动作连贯性略降 |
| SageAttention | +80% 吞吐（非 offload 瓶颈时） | 24GB offload 场景反而更慢，**必须实测** |
| RIFE 插帧 24→48fps | 观感提升 | 每 5s +30s |
| 544p → 超分 1080p | 产能 2× | 每 5s +40s |
| 批处理（同参数连跑） | 免去模型重载 -20% | 需改 worker 支持 |

## 10. 不做什么

| 想法 | 为什么不做 |
|---|---|
| 加 Redis/Celery | 单机单卡，SQLite 队列够 |
| 前端上 React/Vue | 单页原生 JS 已够，省构建链 |
| 上 Kubernetes | 一台机器，docker compose 是正解 |
| 做多租户 | 自用，不需要 |
| 分布式渲染 | 一张卡，加卡也先做多进程调度不搞分布式 |
