# 示例人物A项目问题分析（2026-10-23）

分析对象：`示例人物A / E1 跳起来的那一下`（75 镜 / 600 秒 / 单角色 / 单场景）
现象：① 人脸与输入照片差异明显 ② 分镜头大量重复 ③（附带发现）37 镜渲染失败

| # | 问题 | 根因 | 性质 |
|---|---|---|---|
| 1 | **人脸不像** | **Ref2VA 参考图实际未生效**——换参考图输出逐字节不变 | 代码/接线缺陷（可修） |
| 2 | **37 镜失败** | v0.6 重构时漏了首帧上传，导致 100% 奇偶交替失败 | **已修复并验证** |
| 3 | **镜头重复** | 剧本本身是「单场景·单动作·600 秒」，分镜规则没拦住 + 尾帧衔接把画面焊死 | 规则/输入问题 |

## 二、人脸问题（最关键）

### 2.1 实测证据

同一张参考照片、同一句提示词、同一 seed，只改「参考图输入方式」：

| 变体 | 参考图处理 | 结果 |
|---|---|---|
| A | 长锚点文本 + Ref2VA（原样） | 亚洲男性、戴眼镜、深色外套 —— **方向对，但不是本人**（年龄偏大、脸更宽、眼镜变半框） |
| B | 中性短提示 + Ref2VA | **欧美男性、深蓝西装** —— 完全跑偏 |
| B′ | 同 B，但参考图换成**纯脸部特写** | **与 B 的抽帧 md5 完全相同**（`6be2e144c07f...`） |
| C | 中性短提示 + 不用 LoRA + 20 步 | 另一个欧美西装男 |
| E | Ref2VA + `ref_image_size=max`（官方称保真最好） | 欧美西装男，无改善 |
| **D** | **FL2VA（参考图当首帧）** | **明显接近本人**：眼镜/发型/脸型都对上，0.5s→2.5s 面部无漂移 |

**决定性一条**：B 与 B′ 参考图完全不同（整图 1800×1200 vs 640×640 脸部特写），
**输出帧 md5 逐字节相同** → 参考图对生成结果**零影响**。

### 2.2 这意味着什么

- 现在的 Ref2VA 分支里，人物长相**只由文本决定**（所以 A 变体比 B 好——A 有详细文字锚点）
- 参考图仅"上传成功、接到节点上"，但**没有进入采样**（ComfyUI 侧 `MiniMaxH3ReferenceToVideo`
  的 reference latent 疑似未生效，具体是节点内部对 int8 剪枝模型的处理问题，需要继续挖 ComfyUI 源码）
- 而 **FL2VA 首帧模式实测能锁住脸**（D 变体）

### 2.3 次因（即使 Ref2VA 修好也存在）

- 用户原图是**全身半身照**，人脸只占画面约 8%×12%，参考信号极弱
- 角色 `appearance` 写的是「中年戴黑框眼镜…圆脸」，是**概括词**而非可复现的锚点
  （年龄、脸型、五官比例、发际线、眼镜框型都没锁死）

## 三、37 镜失败（已修复）

### 3.1 现象

```
成功：1,3,5,...,75（38 镜）
失败：2,4,6,...,74（37 镜）  ← 100% 奇偶交替
错误：LoadImage - Invalid image file: /output/.../sh_xxx_lastframe.png
```

### 3.2 根因

v0.6 加 Ref2VA 分支时，把「首帧必须先上传到 ComfyUI input 目录」这一步
**只留在了 `use_ref` 分支里**，FL2VA 分支漏掉了：

```
镜1  无首帧 → 走 Ref2VA → 成功
镜2  继承镜1尾帧（/output/... 绝对路径）→ use_ref=False → 未上传 → LoadImage 报错 → 失败
镜2  失败后 prev_last_frame 被清空
镜3  又回到 Ref2VA → 成功
⇒ 奇偶交替
```

### 3.3 修复

`pipeline/worker.py`：只要走 FL2VA 且首帧仍是绝对路径，一律先 `upload_image`。
单测 `scripts/test_firstframe_upload.py` 已通过：

```
✅ 首帧被上传
✅ 提交的图: LoadImage image=['uploaded_fake_lastframe.png']
```

## 四、镜头重复（三个叠加因素）

### 4.1 输入侧：剧本本身没有镜头变化

原剧本是 600 秒的「时序动作分解」：

```
0-120s   面带笑容慢慢向后退步
120-260s 持续后退，双脚蓄力
260-380s 跳起，双臂张开，唱《今天是个好日子》
380-500s 落地，继续小幅度蹦跳演唱
500-600s 放缓收尾
```

**单场景 + 单角色 + 一条连续动作**。系统按 8 秒一镜切成 **75 镜**，
切出来的必然是「同一个人在同一走廊后退」×N。

### 4.2 规则侧：没有拦住「无变化」

- 分镜规则里"镜头数 20-24"是建议值，用户传入 600 秒时按 8 秒/镜自然算出 75 镜
- 没有任何规则检查"这一镜和上一镜的视觉差异是否足够"
- 实测 38 个成功镜里：`木纹` 出现 30/38、`笑容/微笑` 11/38、`后退` 8/38、
  机位 `跟` 占 23/38

### 4.3 渲染侧：尾帧衔接把画面焊死

`chain_frames: true` 让每镜从上一镜的最后一帧开始 —— 好处是连贯，
代价是**后面 74 镜等于同一条镜头的延长**，观众看到的就是"一直在同一个位置后退"。

## 五、解决方案（请决策）

### 5.1 人脸保真 —— 三选一（可组合）

| 方案 | 做法 | 预期效果 | 代价 |
|---|---|---|---|
| **F1 改回 FL2VA 首帧锁定**（推荐，已实测有效） | 每镜用**角色定妆照**当首帧（而不是上一镜尾帧），Ref2VA 暂时关掉 | 脸与照片一致（D 变体实测），全片统一 | 每镜构图都从同一张定妆照起步，**姿态变化受限**（要靠镜头运动/场景变化制造差异） |
| **F2 修 Ref2VA 接线** | 继续挖 `MiniMaxH3ReferenceToVideo` 源码，确认 reference latent 是否被 int8 模型忽略；可能要换 `h3-fl2va` 模型配 reference 节点 | 修好后能同时锁脸 + 自由构图（最优解） | 需要 1-2 天调试，且不保证修好（可能是模型本身限制） |
| **F3 后期换脸** | 生成后用换脸模型把脸替换成照片（当前节点里只有 `PhotoMaker*`，没有 ReActor/insightface） | 脸 100% 一致 | 需装 ComfyUI 换脸插件 + 模型（约 2-4GB）；口型/表情可能略僵 |

**我的建议**：先上 **F1**（今天可用、已实测），把这一集重新渲出来；
同时评估 **F2**（真正的长期解）。

### 5.2 镜头重复 —— 两条路

| 方案 | 做法 | 说明 |
|---|---|---|
| **R1 改脚本结构** | 把 600 秒单场景拆成**多场景短剧**：换地点（走廊→电梯→房间）、换景别节奏、加第二角色互动 | 从源头解决。600 秒一集本身也不符合短剧节奏（通常 60-120 秒/集） |
| **R2 加"重复检测"规则** | 分镜生成后自动检查：相邻镜的动作相似度、机位分布、景别分布；不达标就要求 LLM 重拆 | 通用防线，防止任何剧本切出"复制粘贴镜头" |
| **R3 关掉尾帧衔接** | `chain_frames: false`，每镜独立生成 | 画面差异立刻变大，但人物/场景连贯性会下降（正好可以配合 F1 定妆照首帧） |

**我的建议**：**R1 + R2**；这一集重做时 **R3 也打开**（配合 F1，每镜从定妆照起步，
构图变化由提示词和机位控制，不再被上一镜焊死）。

### 5.3 立即可做的三件小事

1. 角色 `appearance` 改成**可复现锚点**：具体年龄、脸型（圆/方/长）、眉形、
   发际线、眼镜框型与颜色、痣/疤等特征，逐字复用
2. 参考图改用**脸部占画面 40% 以上的半身照**（Python/ffmpeg 裁一下即可）
3. 单集时长收敛到 60-120 秒（短剧标准），600 秒请拆成 5-8 集
