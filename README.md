# SDF · 短剧工厂

> **一句话故事 → 带对白、音效、字幕的短剧成片**，全流程本地跑，不租云 GPU。

在一台单卡工作站（RTX A5000 24GB）上，从一句故事素材出发，自动完成
**大纲 → 分镜 → 渲染 → 成片**，产出 1 分钟左右的竖屏/横屏短剧视频。

## 为什么做这个

市面上的 AI 视频工具大多是「单镜头生成器」：给一句 prompt 出 5 秒片段，
然后你自己去拼。但短剧不是片段堆叠，它需要**人物一致、场景连贯、
对白对得上口型、镜头之间有节奏**。

这个项目解决的是**流水线**问题：

- 一个故事自动拆成 N 集，每集自动拆成 N 个镜头
- 每镜带景别、机位、光线、台词、音效的结构化描述
- 人物长相靠参考图锁死，跨镜头不换脸
- 渲染排队、断点续跑、失败自愈
- 最后自动拼接、对齐响度、烧字幕、出成片

---

## 五步流程

```
① 输入故事 → ② 剧情大纲 → ③ 锁定基础信息 → ④ 分镜脚本 → ⑤ 渲染成片
                ↓              ↓                  ↓              ↓
           LLM 拆集      锁定角色/场景/风格   中文分镜 + 场次   队列 → 后台串行
                                                                  ↓
                                                    ① 逐镜渲染（H3）
                                                    ② 同场次接帧
                                                    ③ 拼接 + 响度对齐
                                                    ④ 字幕烧录
```

## 技术栈

| 层 | 选型 | 说明 |
|---|---|---|
| 视频生成 | **MiniMax H3**（FL2VA / Ref2VA） | 音视频同生，原生对白 + 口型 |
| 渲染后端 | ComfyUI | 节点式工作流，通过 HTTP API 驱动 |
| 剧本/分镜 | DeepSeek V4.1 Flash / GLM-5.3 | 结构化 JSON 输出，中文提示词 |
| 编排服务 | FastAPI + 原生 JS | 无前端框架，零构建 |
| 存储 | SQLite | 项目/剧集/镜头/任务/产物 |
| 成片 | FFmpeg | NVENC 编码 + EBU R128 + 字幕烧录 |
| 对外接口 | **MCP**（Model Context Protocol） | 9 个工具，可接 CherryStudio / Claude 等 |
| 部署 | Docker Compose | 栈聚合管理 |

## 硬件基线（实测）

| 项 | 值 |
|---|---|
| GPU | **RTX A5000 24GB**（Ampere sm_86，768 GB/s） |
| CPU | Threadripper 2990WX 32C/64T |
| 内存 | 64GB DDR4（**建议 128GB**） |
| 存储 | NVMe 1.9T（模型权重约 60GB） |
| 系统 | Linux + Docker + NVIDIA Container Toolkit |

**三条硬约束**（都是踩出来的）：

1. **内存比显存重要**。H3 采样时只有 ~6.6GB 真在显存，其余权重在 host RAM 里来回搬。
   host RAM 不够 → 进程被静默 OOM 杀掉，**没有任何 CUDA 报错**。
2. **一次只跑一个渲染任务**。24GB 卡 H3 峰值 22GB，并发必炸。
3. **提示词用中文**。H3 原生支持中文，人物/服装/情绪描述比英文更准。

## 实测性能

**单镜耗时**（A5000 24GB，H3 单卡串行）：

| 分辨率 | 时长 | 耗时 | 备注 |
|---|---|---|---|
| 1344×768（质量档） | 6-7 s | **14-27 min** | 有对白的镜走 12 步，更慢 |
| 1280×720（普通档） | 6-7 s | 13-19 min | 默认 |
| 960×544（草稿档） | 5 s | 6-7 min | 试片用 |

**整集产能**：9 镜约 3 小时，17 镜约 6.5 小时。

**成片链路**（额外开销，秒级）：

| 阶段 | 耗时 |
|---|---|
| 统一规格（h264_nvenc） | 40 s / 40 段 |
| 无损拼接（-c copy） | 3.5 s |
| 响度对齐 + 归一 | 20-60 s |
| 字幕烧录 | 0-15 s |

**资源占用**：768p 渲染时显存峰值 22.1/24.5GB、温度 85°C、功耗 227W。

## 关键设计决策

### 1. 为什么用 Ref2VA 而不是首帧锚定

首帧锚定只管开头几秒，镜头一长人物就漂。Ref2VA 把参考图作为
**identity token 参与每一步采样**，整段视频长相稳定。

**实测结论（有 A/B 对照）**：

| 配置 | 人脸像素 | 耗时 | 效果 |
|---|---|---|---|
| `ref_image_size=match` | ~166px | 18-27 min | 显老、脸变宽 |
| **`ref_image_size=max`** | **~410px** | **14.2 min** | **接近本人** |

> 反直觉的地方：`max` 不但更准，**还更快**。因为 `match` 缩小参考图省的
> 那点显存，远不够抵掉质量损失带来的重渲成本。

**还有个坑**：长文字外貌锚点（"圆脸、黑框眼镜…"）会**盖过参考图**，
把模型往"通用中年男"方向拉。有参考图时应改成
`长相严格参考 <Picture 1>`，并把镜头描述里的外貌形容词剥掉。

### 2. 为什么逐镜响度对齐

单遍 `loudnorm` 只保证整条符合目标响度，管不住**镜头之间**的跳变。

实测某片：镜1 -40.9dB → 镜2 -20.7dB（**突变 20 分贝**）→ 镜7 -36.5dB。
听感就是"一会儿听不见、一会儿吓一跳"。

解法：逐镜朝 -18 LUFS 靠，但**限幅 ±12dB**——
纯环境声镜头硬拉会把底噪一起放大 30 分贝。修完最大跳变降到 8.9 分贝。

### 3. 为什么同场次才接帧

把上一镜尾帧当下一镜首帧，能减少画面跳变。但**跨场次接帧会溶解变形**：
模型被迫在两个完全不同的空间之间做形变。

规则：只在同一 `scene_id` 内接帧，跨场次让模型重新建场。

### 4. 一人一图，对话用画外音

只有一张参考图时，多角色对话必然有人脸跑偏。可行做法：
**让有图的角色承担全部露脸戏，其他角色通过对讲机/电话出声**。

这样脸 100% 锁住、对白也够，代价是没有真正的双人对手戏。

## 快速开始

### 前置

- NVIDIA GPU ≥ 24GB 显存，驱动 + Container Toolkit
- Docker + Docker Compose v2
- H3 模型权重约 60GB（从 ModelScope 下载，HF 速度不可用）

### 启动

```bash
git clone <this-repo> sdf && cd sdf

# 1. 环境自检
./deploy/check_env.sh

# 2. 起栈（栈名必须为 sdf）
docker compose -p sdf up -d

# 3. 验证
./deploy/check_stack.sh
curl -s localhost:8080/api/health
```

### 界面

| 地址 | 用途 |
|---|---|
| `http://<server>:8080` | 创作界面（五段流程） |
| `http://<server>:8080/admin` | 后台（设置/模型/提示词/路由/任务） |

---

## MCP 接口

内置 MCP server，任何支持 **Streamable HTTP** 的客户端都能接。

**端点**：`http://<server>:8080/mcp`

### CherryStudio

设置 → MCP 服务器 → 添加 → 类型选「可流式传输的 HTTP」：

- 名称：`sdf`
- URL：`http://<server>:8080/mcp`
- 密钥/Header：留空

### OpenClaw

```bash
openclaw mcp add sdf \
  --transport streamable-http \
  --url http://<server>:8080/mcp \
  --timeout 120
openclaw mcp probe sdf    # 应显示 9 tools
openclaw mcp reload       # 当前会话生效
```

> ⚠️ 两个易错点：OpenClaw 的配置键是 `mcp.servers`（不是 `mcpServers`）；
> 传输字段写 `transport: "streamable-http"`。

### 9 个工具

| 工具 | 参数 | 作用 |
|---|---|---|
| `sdf_list_projects` | `include_archived?` | 列出所有项目 |
| `sdf_get_project` | `pid` | 项目详情（含锁定信息） |
| `sdf_list_episodes` | `pid` | 列出剧集 |
| `sdf_get_episode` | `eid` | 剧集详情（含分镜） |
| `sdf_list_shots` | `eid` | 分镜列表 |
| `sdf_get_prompt_preview` | `sid` | **渲染前预览完整提示词** |
| `sdf_render_episode` | `eid`, `tier?`, `max_shots?` | 触发渲染 |
| `sdf_get_task` | `tid` | 查渲染进度 |
| `sdf_list_artifacts` | `eid` | 查成片与产物 |

> 推荐流程：先 `sdf_get_prompt_preview` 审稿，再 `sdf_render_episode(max_shots=2)` 小样试渲，
> 确认无误才跑全集。渲染是异步长任务，用 `sdf_get_task` 轮询。

## 配置

所有配置在 `config/` 下，6 个 YAML：

| 文件 | 内容 |
|---|---|
| `settings.yaml` | 运行参数（画幅/帧率/超时/响度/字幕样式） |
| `models.yaml` | 模型注册表（含 sha256 校验） |
| `prompts.yaml` | LLM 提示词模板 |
| `routing.yaml` | 引擎路由规则 |
| `engines.yaml` | 采样参数、帧数规则、LoRA |
| `presets.yaml` | 11 个中文风格预设 + 平台规格 |

**三种改法**：宿主机直编 / 后台表单 / `PUT /api/admin/config`。
改完点「重载配置」即时生效，不用重建镜像。写前自动备份 `.bak.时间戳`。

### 配置发布（重要）

配置和代码**分开发布**。`config/` 是运行时真实配置，不能整文件覆盖：

```bash
python3 deploy/publish_config.py --dry-run   # 看会改什么
python3 deploy/publish_config.py             # 合并式发布
```

规则：内容库（风格/提示词，以仓库为准）+ 运行时参数（画布/帧率/字幕，保留线上值）。

## 已知限制

诚实列出当前做不到的：

1. **单角色锁脸有效，多角色仍是难题**——没有参考图的角色无法稳定复现
2. **H3 不能生成正确文字**——门牌、证件、招牌类特写会出现乱码
3. **对白需刻意设计**——LLM 默认分镜很"静"，要显式要求每 6 秒一句台词
4. **参考图会污染构图**——需在提示词里明确「只管长相，不管构图」
5. **AI 超分未接**——目前仅 Lanczos 重采样

## 踩过的坑（部分）

完整 18 条见 [`docs/06-踩坑记录.md`](docs/06-踩坑记录.md)。几个典型：

| 坑 | 症状 | 根因 |
|---|---|---|
| 配置改了不生效 | 代码对、界面没变 | `rsync --ignore-existing` 把正常发布也挡了 |
| 队列不推进 | status=running 但一镜不动 | 用了未定义变量，消费者每拿到项就崩 |
| 页面报 null | 组合面板看着是空的 | `await` 期间第二次 render 销毁了 DOM |
| 锁定页卡 6 秒 | 停在"加载中…" | 每次进页面都重新调 LLM |
| 人脸不像本人 | 同类人但不是同一人 | 长文字锚点盖过参考图 + 参考图被压缩 |

> 这些的共同点：**接口通、状态看着对、实际不动**。
> 所以验证必须看产物像素，不能只看流程跑通。
